# 관리자 대시보드 — 방문 · 흐름 · 장사 · 앱 통계 한 화면 — 설계

> 2026-10-26. 요청(형 원문 요지): 「어드민 대시보드 같은 거도 만들까 싶어. 도메인별로. 축하 페이지 앱 같은 경우는 템플릿 뭐 썼는지나 샘플에서 넘어가는 게 어디 게 많은지 어떤 태그가 많은지 등 … 접속 현황이나 이런 거도 있음 좋고. 그냥 보통 대시보드 느낌으로」.
> 대상: kotlin-skeleton(새 `dashboard` · `dashboard-jdbc` · `dashboard-cloudflare` · `dashboard-ga`, 기존 `account` · `payment` 가 카드 기여, `apps/sample`) + react-skeleton(새 `@skeleton/dashboard`, `@skeleton/marketing` 에 GA · CF 비콘 켜기, `apps/sample`).
> 화면 시안: 시안 E(실제 대시보드 관행을 따른 것) — 홈서버 `.share/dashboard-mock/e.html`. A~D 는 거쳐 간 시안.
> 사례 조사(2026-10-26 researcher): Plausible · Vercel · PostHog · GA4 · Stripe · Shopify · shadcn 예시. 공통 패턴은 §4.

## 0. 목표 · 비목표 · 반목표

**목표**: 스켈레톤으로 찍은 앱이 설정 몇 줄로 「보통 대시보드」 한 화면을 얻는다 — 방문 · 가입 · 활성 · 매출 · 결제 숫자와 추이, 유입 · 페이지 · 지역, 퍼널, 그리고 앱이 붙이는 도메인 통계. 형이 축하 페이지 앱에서 하루 장사를 한눈에 보고, GA · Cloudflare 화면을 따로 열지 않는다.

**비목표(이번에 안 함)**
- 항목을 누르면 대시보드 전체에 필터가 걸리는 것(Plausible 식). 숫자 출처가 셋(CF · GA · 우리 DB)이라 한 필터가 세 곳에 같은 뜻으로 걸리지 않는다. 넣을 자리: 카드 API 에 `filter` 인자를 열어 두지 않는다 — 출처별 필터 어휘가 생기면 그때.
- CSV 내보내기, 임계값 알림, 사용자가 차트를 직접 만드는 기능, GA 경로 탐색(Sankey) 그림.
- 대시보드 숫자를 다른 서비스로 보내기(웹훅 · 메일 리포트).
- 앱 고유 도메인 카드 자체(템플릿 · 샘플 출처 · 태그). 스켈레톤은 카드를 붙이는 틀과 견본 앱의 예시 카드만 — 그 카드는 해당 앱 쪽 작업.
- 운영자 행동 기록(앞선 권한 설계의 결정 3 그대로).

**반목표(이렇게 되면 기술적으로 돌아도 실패)**
- 대시보드 때문에 서버가 무거워진다(외부 API 를 화면 열 때마다 직접 부르기, 원본 이벤트를 우리 DB 에 쌓기).
- 개인을 알아볼 수 있는 값(IP · 이메일 · 계정 id 목록)이 대시보드 표에 저장된다. 대시보드 표는 **집계 숫자만** 갖는다.
- 키(CF 토큰 · GA 서비스 계정 키)가 없으면 앱이 안 뜬다. 출처가 없으면 그 카드만 「연결하면 보입니다」 빈 상태다.
- 스켈레톤 기본값이 바뀐다 — `dashboard` 를 붙이지 않은 앱은 아무것도 달라지지 않는다(스켈레톤 중립 원칙).

## 2. 모듈과 확장 지점

| 모듈 | 하는 일 | 빼면 |
|---|---|---|
| `dashboard` | 계약(아래) · 관리 API · 권한 `dashboard.read` 선언 · 카드 조립 · 짧은 캐시 | 대시보드 없음 |
| `dashboard-jdbc` | 일별 적재 표(`dashboard_traffic_daily` 등 — §3.3) · 계정별 화면 설정 표 | 외부 출처(CF · GA)의 지난 기간이 없다(오늘 · 실시간만), 화면 설정은 기기별(브라우저 저장)로 물러난다 |
| `dashboard-cloudflare` | CF GraphQL Analytics 읽기 — 새벽 적재 작업 + 오늘 근실시간 | 방문 타일 · 유입/페이지/국가/기기 카드의 CF 탭이 빈 상태 |
| `dashboard-ga` | GA4 Data API(일별 적재) + Realtime API(현재 방문자) | GA 탭 · 재방문율 · 현재 방문자가 빈 상태 |

**계약(`dashboard`)** — 모듈 · 앱이 빈으로 기여한다. 카드 꼴은 셋뿐(시안 E):
- `DashboardMetric` — 타일 하나: `key` · 이름 · 단위(명 · 건 · 원 · %) · `value(range)` · `series(range, interval)`(시간/일/주 — 「오늘」 · 하루 범위는 시간별, 내 판단: 시안 E 와 실제 대시보드 모두 오늘을 시간별로 그린다. GA 는 오늘 숫자가 없어 오늘 시간별 그래프에서 빠지고 빈 상태 안내). 직전 기간 값은 같은 함수에 직전 범위를 넣어 얻는다. 출처 배지 · 신선도(`freshness`: 실시간 / n분 전 / 어제치) 를 같이 돌려준다.
- `DashboardRanking` — 순위 카드의 탭 하나: `key` · 카드 묶음(`traffic` · `pages` · `geo` · `app`) · 열 이름 · `top(range, limit)` · 신선도.
- `DashboardFunnel` — 같은 사람 묶음 퍼널(내 판단 — 형이 받아들인 설명 「샘플 봄 → 만들기 → 결제까지 단계별로 몇 % 가 남나」가 같은 사람 기준이고, 타일 숫자를 나란히 놓으면 128 → 912 → 87 처럼 뒤 단계가 커져 퍼널로 읽히지 않는다). 첫 단계가 묶음(기간 안에 들어온 계정)을 정하고, 다음 단계마다 「그 묶음 중 이 단계에 닿은 계정 수」를 센다. 단계는 `DashboardFunnelStep` 빈(이름 · `reached(cohort, range)`)이고 타일 key 와 따로다. 기본 빈은 가입 → 활성 → 결제 — 가입 · 활성 단계는 `account` 가, 결제 단계는 `payment` 가 기여하고, 묶음은 계정 id 목록이 아니라 「가입 시각 범위」 조건으로 넘겨 모듈끼리 서로를 모르게 한다(각 모듈이 자기 표에서 계정 id 로 거른다 — 정확한 질의 모양은 빌더 몫). 방문(CF)은 익명이라 퍼널 앞에 참고 숫자로만 붙인다. 앱이 같은 이름 빈을 두면 기본 퍼널이 물러난다(축하 페이지 앱: 샘플 봄 → 만들기 → 발행 → 결제 — 「샘플 봄」이 익명이면 같은 방식으로 참고 숫자).
- 권한: `dashboard.read` 하나(앞선 권한 체계의 `PermissionDeclaration`). 매출 숫자를 가릴 세부 권한은 두지 않는다 — 1차 비목표.

**기본 기여**
- `account`: 신규 가입(기간 내 가입 수 · 누적), 활성 이용자(기간 내 로그인 · 토큰 갱신이 있었던 계정 수 — 정의는 §6 빌더 몫).
- `payment`: 순매출(결제 − 환불, 통화별 — §6), 결제 건수. 타일에 「정확한 금액은 결제 내역」 링크(Stripe 관행: 홈 숫자는 요약).
- `dashboard-cloudflare`: 방문 · 페이지뷰(타일 · 그래프), 유입 소스 · 많이 본 페이지 · 국가 · 기기(순위).
- `dashboard-ga`: 채널 · 전환, 캠페인(UTM), 첫 페이지, 페이지 이동(A→B: `pageReferrer` → `pagePath` 쌍 상위), 재방문율, 현재 방문자.

## 3. 데이터

### 3.1 우리 DB 숫자
요청 때 계산한다(실시간). 같은 범위 질의는 30초 캐시(대시보드 여러 개가 열려도 DB 를 두드리지 않게). 큰 표 전체를 훑는 질의가 되면 안 된다 — 가입 · 결제 표의 생성 시각 인덱스로 범위를 끊는다(없으면 이번에 마이그레이션으로 더한다).

### 3.2 Cloudflare
- 출처: **Web Analytics(RUM)** — 무료, 쿠키 없음, 주황 구름(프록시)이면 CF 가 비콘을 자동으로 넣는다. 존 HTTP 집계(봇 · 이미지 섞임, 무료에선 페이지뷰 없음)는 쓰지 않는다.
- 읽기: GraphQL Analytics API, 토큰 권한 Account Analytics Read(읽기 전용, 형이 발급해 `.env.local` 에). 한도 5분당 300 질의.
- 적재: 매일 새벽(앱 시간대) 어제치를 `dashboard_traffic_daily` 등에 upsert. CF 보관이 짧아(원본 7일 뒤 표본 축소, 집계 최소 31일) 길게 보려면 옮겨 적어야 한다. 같은 날을 다시 적재해도 같은 결과(멱등).
- **확인 못 한 것(구현 첫 작업으로 토큰을 받아 잰다)**: 무료 계정에서 열리는 데이터셋과 조회 가능 기간, 봇 제외 기본값, `date` 등 필드 이름, 표본 환산(`sampleInterval`). 잰 결과로 이 절을 고친다.

### 3.3 GA4
- 프런트: `@skeleton/marketing` 쿠키 동의의 「분석」에 동의한 방문자만 gtag 를 띄운다(측정 ID 가 있을 때만). 동의 전에는 아무것도 보내지 않는다.
- 읽기: 서비스 계정 키(읽기 전용, GA 속성에 「뷰어」로 추가) — 형이 만들어 `.env.local` 에. 만드는 순서는 문서(`docs/modules/dashboard-ga.md`)에.
- 적재: 매일 새벽 어제치(채널 · 전환 · 캠페인 · 첫 페이지 · 페이지 이동 상위 · 재방문). GA 일반 집계는 몇 시간 늦게 잡히므로 「오늘」은 적재하지 않고 카드에 「GA 기준 n시 집계」를 붙인다.
- 전환: GA 의 핵심 이벤트(key event) 이름을 설정으로 받는다(예: `purchase`). 없으면 전환 열을 숨긴다.

### 3.4 실시간 (결정 6)

| 숫자 | 신선도 | 방법 |
|---|---|---|
| 우리 DB(가입 · 활성 · 매출 · 결제 · 퍼널의 DB 단계 · 앱 통계) | 실시간 | 요청 때 계산 + 30초 캐시. 화면은 열려 있는 동안 60초마다 다시 불러온다(탭이 숨겨지면 멈춤) |
| 현재 방문자(헤더 「지금 N명」) | 1분 | GA Realtime API(최근 30분 활성 사용자 · 지금 보는 페이지 · 유입), 서버 60초 캐시. 누르면 실시간 패널(페이지 · 유입 상위). 쿠키 동의한 사람만이라 「GA · 동의한 방문자」 표시 |
| CF 오늘(방문 · 유입 · 페이지 · 국가) | 약 5분 | 오늘 범위는 CF 를 직접 질의, 서버 5분 캐시. 「약 n분 전 기준」 표시 |
| CF · GA 어제까지 | 어제치 | 새벽 적재분을 DB 에서 |
| GA 오늘(채널 · 전환 등) | 몇 시간 | GA 일반 집계 지연 — 당길 수 없다. 「GA 기준 n시 집계」 |

외부 API 는 화면 요청마다 부르지 않는다 — 서버 캐시가 막는다(반목표 1). 여러 운영자가 동시에 열어도 외부 호출은 캐시 주기당 한 번.

### 3.5 Cloudflare 실측 전 순서 (내 판단)
가짜 CF 서버(기존 `fakePaddle` 방식)로 먼저 짓고, 형이 실제 사이트 토큰을 주면 §3.2 의 미확인 값을 재서 맞춘다. 무료 Web Analytics 에서 어떤 차원(유입 · 경로 · 국가 · 기기)이 안 나오면 그 탭만 뺀다(존 HTTP 집계로 대신하지 않는다 — 결정 2).

### 3.6 여러 프로젝트 모드 (결정 7)
`skeleton.projects` 로 한 프로세스에 여러 프로젝트를 띄우면, 다른 모듈처럼 프로젝트마다 따로 돈다(`docs/multi-project.md`): CF 사이트 태그 · GA 속성 id · 키를 프로젝트별 설정으로, 새벽 적재를 프로젝트마다(`ProjectContext.runIn`), 캐시 키 · 「외부 호출은 주기당 한 번」 단위를 프로젝트별로, 일별 표는 프로젝트 스키마마다. 각 프로젝트 관리자는 자기 프로젝트 대시보드만 본다. 총괄 화면은 없다.

### 3.7 저장 표 (`dashboard-jdbc`)
- 일별 집계: (날짜, 출처, 지표 또는 차원 종류, 차원 값, 숫자) — 정확한 표 모양은 빌더 몫. 개인 식별 값 없음.
- 화면 설정: 계정별 한 줄(꺼진 카드 · 순서, JSON). 계정 삭제(ERASED) 때 같이 지운다.
- 보관: 일별 집계는 지우지 않는다(하루 수십 줄). 

## 4. 화면 (react `@skeleton/dashboard`)

시안 E 를 따른다. 실제 대시보드 공통 패턴(사례 조사):
1. 위 → 아래: 헤더(기간 오늘/7일/30일/직접 · 직전 기간 비교 · 지금 N명 · 편집) → 숫자 타일 → 큰 그래프 → 순위 카드 격자 → 퍼널 → 앱 통계.
2. 타일마다 직전 기간 대비 증감. 타일을 누르면 바로 아래 그래프가 그 지표로(Plausible · Vercel). 타일과 그래프는 한 덩어리로 보이게.
3. 순위 목록은 카드 하나 + 안의 탭, 카드마다 「전체 보기」.
4. 퍼널은 위가 아니라 아래 별도 구역.
5. 카드마다 출처 배지 + 신선도(§3.4). 출처가 없으면 그 카드(또는 탭)만 빈 상태 안내 「Cloudflare 토큰을 넣으면 보입니다」.
6. 편집 모드(Stripe · Shopify): 카드 · 타일 끄기, 카드 순서, 「완료」로 저장(계정별 — `dashboard-jdbc` 없으면 브라우저 저장).
7. 폰: 타일 2열, 카드 1열. 편집은 폰에서도 된다(▲▼ 버튼; 끌어 옮기기는 넓은 화면만).
8. 차트는 가벼운 SVG 컴포넌트로 직접(선 · 막대 · 퍼널 막대) — 차트 라이브러리를 새로 들이지 않는다(내 판단: 카드 꼴이 셋뿐이라 라이브러리 무게가 이득보다 크다). 눌리는 요소는 눌리게 보인다(테두리 · 채움, 글자만 있는 버튼 금지).
9. 라우트 · 메뉴: 관리자 메뉴 첫 항목, `RequirePermission('dashboard.read')`.

## 5. 설정 (키는 모두 `skeleton.dashboard.*`, 비밀은 env)

- `dashboard`: `enabled`(모듈을 붙이면 켜짐), 캐시 주기(DB 30s · CF 오늘 5m · GA 실시간 60s — 기본값만, 앱이 바꿀 수 있음), 시간대(앱 시간대 따름).
- `dashboard-cloudflare`: 계정 id, 사이트 태그(Web Analytics), API 토큰(env).
- `dashboard-ga`: 속성 id, 서비스 계정 키(env, base64 JSON), 전환 이벤트 이름.
- 프런트: `VITE_GA_MEASUREMENT_ID`(있으면 동의 뒤 gtag), `VITE_CF_BEACON_TOKEN`(CF 프록시를 안 거치는 배포에서만).
- 키가 없으면 해당 모듈은 뜨되 카드가 빈 상태(반목표 3). 잘못된 키는 적재 작업 실패로 알림(`alert` 모듈이 있으면) — 기동은 막지 않는다.

## 6. 빌더에게 맡기는 것 (내가 정한 기본값 표시)

- **활성 이용자 정의**: 기간 내 로그인 또는 토큰 갱신이 있었던 계정 수(내 판단). 근거 데이터(`auth-session` 세션 표의 갱신 시각 등)가 없으면 가장 가까운 것을 쓰고 문서에 적는다.
- **순매출 통화**: 여러 통화가 섞이면 통화별로 따로 보여 주고 합치지 않는다(환율 변환은 하지 않는다 — 업계 관행: 결제사 대시보드도 통화별). 타일은 앱 기본 통화, 나머지는 타일 아래 작은 줄.
- 일별 표 모양, 캐시 구현, CF · GA 클라이언트 구조, 새벽 적재 시각(스케줄러 모듈 사용).
- 견본 앱의 「앱 통계」 예시 카드 내용(이미 있는 데이터로).
- 시험: 돈(순매출 계산 — 결제 · 환불 · 부분 환불 · 통화)과 적재 멱등에만 회귀 테스트. 화면은 e2e 한 여정(운영자가 대시보드를 열면 DB 타일이 보이고, 가짜 CF · GA 서버가 준 숫자가 카드에 보이고, 타일을 누르면 그래프가 바뀐다). 가짜 CF · GA 서버는 기존 `fakePaddle` 방식.

## 7. 검증

- 키 없이 견본 앱을 띄우면 DB 타일 · 퍼널의 DB 단계 · 앱 통계는 숫자가 나오고, CF · GA 카드는 빈 상태 안내.
- 가짜 CF · GA 서버로 새벽 적재를 돌리면 일별 표가 채워지고, 다시 돌려도 같은 결과.
- 형이 CF 토큰 · GA 키를 `.env.local` 에 넣고 견본 앱을 띄우면 실제 숫자가 나온다(형 확인).
- 결제 하나를 하고 대시보드를 열어 두면 1분 안에 순매출 · 결제 건수가 바뀐다.
- 폰(390px) · PC(1280px)에서 가로 스크롤 없음.

# 출시 전 체크리스트 — 켜는 기능별

첫 prod 배포 전에 사람이 준비할 것. 갈래는 매출 규모가 아니라 **무엇을 받느냐**로 정한다. 로그인 · 광고 · 결제 · 메일 가운데 무엇을 켰는지 보고 해당하는 절만 하면 된다. 법률 검토를 거치지 않은 정리다. 방침과 약관 본문은 주인이 검토를 받는다([legal](legal.md) §3).

## 0. 갈래

| 켠 것 | 개인정보 처리방침 | 이유 |
|---|---|---|
| 없음(로그인 X · 광고 X) | 거의 필요 없음 | 서버가 IP 를 로그로 남기면 한 줄 적어 두는 게 안전하다 |
| 로그인(소셜 포함) | **필요** | 무료 서비스여도 개인정보보호법 대상 |
| 광고 | **필요** | 쿠키 · 광고 식별자는 행태정보. 광고 플랫폼 정책도 방침을 요구한다 |
| 결제 | 필요 + 사업자 표시 | 전자상거래법 |
| 메일 발송 | 필요(위탁 업체 한 줄 추가) | |

**가드:** prod 에서는 예시 문서(`template: true`)가 막히고, 문서가 쓰는 `{{키}}` 가 `skeleton.legal.facts.*` 에 없으면 기동이 멈춘다([legal](legal.md) §3 체크리스트). 아래 값을 문서에 `{{키}}` 로 넣으면 비었을 때 같은 가드가 잡는다. 결제 · 메일 전용 값은 그 기능의 문단에만 넣는다. 그러면 기능을 켠 서비스에서만 검사된다.

## 1. 로그인을 켜면

- **방침에 넣을 값**
  - 문의 메일
  - 개인정보 보호책임자: 개인 이름 대신 「○○ 운영팀」처럼 부서로 적어도 된다
  - 저작권 · 신고 담당 메일
  - 처리를 맡긴 업체(서버 · DB · CDN)와 처리 위치
  - 업체별 개인정보 문의처(국외 이전 고지)
- **업체 문의처** (각 업체 공식 방침에서 2026-11-23 확인)

  | 업체 | 문의처 |
  |---|---|
  | Cloudflare | `privacyquestions@cloudflare.com` |
  | PlanetScale | `privacy@planetscale.com` |
  | Google Cloud(한국) | `googlekrsupport@google.com` 또는 Privacy Help Center |

  - 서버를 계약한 법인 이름은 결제 화면이나 계약서에서 확인한다. 짐작으로 적지 않는다.
- **받는 메일 주소** (`contact@` · `privacy@` · `report@`): Cloudflare Email Routing 으로 주인 메일에 전달하면 메일 업체를 따로 쓰지 않아도 된다.
- **소셜 앱:** dev 와 prod 를 따로 만든다. 두 앱은 서로 영향을 주지 않는다. prod 주소의 redirect 는 prod 앱에만 등록한다([real-provider-setup](real-provider-setup.md) §0~4).
  - **카카오:** 비즈 앱이 아니면 이메일 권한을 받을 수 없다. 이메일 없이 가입하는 흐름이 되는지 먼저 확인한다.
  - **네이버:** 검수 신청은 서비스 주소가 실제로 열린 뒤에 할 수 있다.
  - **구글:** 동의 화면에 방침 · 약관 주소가 들어간다. 방침 페이지를 먼저 공개해 둔다.

## 2. 광고를 켜면 (안 켰으면 통째로 건너뛴다)

- **계정**
  - 웹 보상형 광고(GPT `OutOfPageFormat.REWARDED`, `ads-web-rewarded`)는 **Google Ad Manager** 가 있어야 한다. AdSense 만으로는 안 된다.
  - Ad Manager 는 보통 승인된 AdSense 계정이 먼저 있어야 한다. 사업자가 없는 개인도 만 19세 이상이면 가입할 수 있다.
- **심사**
  - 최상위 도메인 단위로 받는다. 서브도메인은 승인 뒤 따라오고, 다른 도메인은 사이트를 추가해 따로 심사받는다.
  - 공개된 사이트가 있어야 신청할 수 있고, 며칠에서 2~4주 걸린다.
  - 서버를 올리기 전에 정적 홈과 방침 페이지부터 공개하고 바로 신청하는 편이 빠르다.
- **방침과 동의**
  - 방침에 광고 쿠키 · 광고 식별자 · Google 위탁 · 국외 이전을 고지한다.
  - 쿠키 동의에 광고 범주를 둔다. 동의 전에는 제한 광고만 내보낸다.
  - EEA · 영국 · 스위스 방문자에게는 인증받은 CMP 가 필요하다. Ad Manager 의 「Privacy & messaging」으로 할 수 있다.
- **사이트:** CSP 에 GPT 도메인을 열고 `ads.txt` 를 올린다.
- **광고를 끈 배포:** 광고에 기대는 기능이 같이 죽지 않게 대체 경로를 둔다. 예를 들어 보상형 광고로 여는 기능은 광고가 없을 때 작은 무료 한도로 연다.

## 3. 결제를 켜면

- 화면에 표시할 것:
  - 상호
  - 대표자
  - 사업자등록번호
  - 통신판매업 신고번호
  - 주소
  - 전화
  - 호스팅 제공자
- 사업자 등록을 먼저 한다. 제공자별 준비는 [real-provider-setup](real-provider-setup.md) §11~14 를 본다.

## 4. 메일 발송을 켜면

- 방침에 메일 업체(위탁)와 그 업체의 국외 이전 문의처를 더한다([real-provider-setup](real-provider-setup.md) §5).

## 5. 클라우드 계정 (겪은 순서)

1. **GCP**
   - 결제 계정은 **개인 결제 프로필**로 만든다. 비즈니스 프로필은 사업자 칸에서 막힌다.
   - 예산 알림(원화 상한)부터 걸어 둔다.
2. **PlanetScale(PostgreSQL)**
   - 클러스터 하나에 DB 를 둘로 나눈다(`<서비스>_prod` · `<서비스>_dev`). 역할도 DB 마다 따로 둔다.
   - 대시보드에서 만든 역할로는 SQL 로 DB 소유권을 넘길 수 없다. 그래서 소유자는 `postgres` 로 두고, 앱 역할에는 CREATE 와 `public` 스키마 권한을 준다.
   - 웹 콘솔은 `postgres` 권한으로 붙는다. `REVOKE CONNECT … FROM PUBLIC` 을 할 때 `postgres` 의 CONNECT 는 남긴다.
   - 「production 브랜치 웹 콘솔 접근」 스위치와 「DB 삭제 막기」 설정을 확인한다.
3. **Secret Manager:** 비밀을 넣고, `secretAccessor` 권한은 서버 서비스 계정에만 준다([deploy-cloudrun](deploy-cloudrun.md) §1~2).
4. **콜드스타트**
   - JVM 은 십수 초 걸린다.
   - 네이티브 이미지나 CRaC 로 줄인다([native-image](native-image.md)).
   - CRaC 이미지에는 비밀이 그대로 남는다. 그래서 빌드 전용 서비스 계정을 쓰고, 키를 회전하면 이미지를 다시 굽는다.
